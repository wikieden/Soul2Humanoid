# 具身智能大空间目标重定位方案对比

> **调研时间**: 2026-05-23  
> **核心问题**: 机器人在大空间中如何找到之前看到的某个物体？  
> **调研公司**: Figure AI、Physical Intelligence、1X Technologies、Tesla Optimus、Google DeepMind、NVIDIA Isaac、Skild AI

---

## 一、问题定义

```
场景：机器人在客厅看到钥匙 → 走到厨房 → 需要回到客厅找钥匙

三大子问题：
1. 记忆：如何记住"钥匙在客厅茶几上"？
2. 导航：如何从厨房回到客厅茶几？
3. 重识别：如何确认找到的就是之前那把钥匙？
```

## 二、各公司方案详解

### 2.1 Figure AI — Helix 三层架构 (S0/S1/S2)

**核心机制**：异步潜向量传递 + 外部空间记忆（推测）

```
┌─────────────────────────────────────────────────────────┐
│ 外部空间记忆系统 (推测独立于 Helix)                        │
│                                                          │
│ ├── 语义地图: 节点("客厅茶几") + 边(可达性) + 关联物体      │
│ ├── 物体实例记忆: "钥匙_001" + 坐标 + CLIP 特征 + 时间戳   │
│ └── SLAM 系统: 精确空间坐标和导航                          │
└─────────────────────────────────────────────────────────┘
         ↕ (S2 查询/更新)
┌─────────────────────────────────────────────────────────┐
│ S2 (7B VLM, 7-9 Hz) — "大脑皮层"                         │
│                                                          │
│ 当收到"去找钥匙"指令时:                                    │
│ 1. 查询外部记忆: "钥匙最后在哪里？" → "客厅茶几"             │
│ 2. 生成子任务序列: 导航到客厅 → 搜索茶几 → 抓取             │
│ 3. 输出潜向量: [子任务: 导航到客厅]                        │
│    ↓ 写入共享内存                                         │
└─────────────────────────────────────────────────────────┘
         ↕ (异步读取)
┌─────────────────────────────────────────────────────────┐
│ S1 (80M Transformer, 200 Hz) — "小脑"                    │
│                                                          │
│ 输入: 头部相机 + 掌心相机 + 指尖触觉 + 本体感觉 + S2 潜向量 │
│ 处理: 多尺度立体视觉 → 交叉注意力 Transformer              │
│ 输出: 全身关节目标                                        │
└─────────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────────┐
│ S0 (10M 神经网络, 1 kHz) — "脊髓"                        │
│ 输入: S1 关节目标 + 当前状态                               │
│ 输出: 关节级执行器命令 (扭矩/位置)                         │
└─────────────────────────────────────────────────────────┘
```

**记忆传递方式**：
- S2 输出连续潜向量 (latent goal vector)，写入共享内存
- S1 每 5ms 读取最新潜向量，投影到 token 空间，与视觉特征拼接
- 异步通信：S2 慢思考 (7-9Hz)，S1 快执行 (200Hz)

**优点**：
- 频率解耦，低延迟反馈
- 信息压缩：7B 模型理解压缩到固定维度
- 容错性：S2 卡顿时 S1 仍能基于上一个潜向量执行

**缺点**：
- 信息瓶颈：复杂任务需要更大 latent_dim
- 单向通信：S2 → S1，没有反馈通道
- 不可解释：潜向量是黑盒，难以调试
- 无显式长期记忆：S1 只有 6-54 秒视觉记忆

### 2.2 Physical Intelligence — π0.7 + MEM

**核心机制**：双尺度记忆 (视频短期 + 语言长期) + 视觉子目标

```
┌─────────────────────────────────────────────────────────┐
│ 高层策略 π_HL (低频 ~0.25Hz)                              │
│                                                          │
│ 输入: 当前观测 o_t + 语言记忆 m_t + 任务目标 g             │
│ 输出:                                                    │
│   ├── 子任务指令 l_t+1: "拿起碗"                          │
│   ├── 更新语言记忆 m_t+1: "已把盘子放进柜子，现在拿起碗"    │
│   └── 视觉子目标图像 (轻量世界模型生成)                     │
└─────────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────────┐
│ 低层策略 π_LL (高频 50Hz)                                 │
│                                                          │
│ 输入:                                                    │
│   ├── 短期视觉记忆 o_t-K:t (6-18 帧，时空分离注意力)        │
│   ├── 子任务指令 l_t+1                                    │
│   └── 任务目标 g                                         │
│ 输出: 高频动作序列 a_t:t+H (Flow Matching)                │
└─────────────────────────────────────────────────────────┘
```

**记忆机制详解**：

| 记忆类型 | 实现 | 时长 | 内容示例 |
|---------|------|------|---------|
| **短期视觉记忆** | 高效视频编码器 (时空分离注意力) | 6-54 秒 | 最近几帧的密集视觉信息 |
| **长期语言记忆** | LLM 压缩摘要 | 15 分钟+ | "已把所有盘子放进柜子" |

**语言记忆压缩示例**：
```
原始事件序列：
  "拿起绿盘子" → "放进柜子" → "拿起黄盘子" → "放进柜子"

LLM 压缩后：
  "已把所有盘子放进柜子"

好处：
- 过滤失败尝试
- 保持上下文窗口可控
- 避免训练-推理分布偏移
```

**π0.7 的视觉子目标**：
- 轻量世界模型生成未来状态的图像
- 每 4 秒或语义意图变化时刷新
- 异步推理：VLA 始终使用最新的子目标

**优点**：
- 显式长期记忆：语言摘要可解释
- 上下文自适应：能从失败中学习调整策略
- 组合泛化：类似 LLM 的技能重组能力

**缺点**：
- 语言表达能力有限：复杂空间关系难以用语言精确描述
- 视觉子目标依赖世界模型质量
- 15 分钟仍是上限，跨小时级任务需要额外机制

### 2.3 1X Technologies — World Model + Redwood VLA

**核心机制**：世界模型预测未来 + VLA 直接执行 + 认知预测头

```
┌─────────────────────────────────────────────────────────┐
│ 1XWM (14B 视频生成模型) — 虚拟仿真器                       │
│                                                          │
│ 预训练: Web 规模视频 → 中对齐: 900h 人类视频 → 微调: 70h  │
│ 输入: 起始帧 + 文本提示 + 动作序列                         │
│ 输出: 预测的未来视频帧                                    │
│    ↓                                                    │
│ IDM (Depth Anything + Flow Matching)                     │
│ 输出: 精确动作序列                                       │
└─────────────────────────────────────────────────────────┘
         ↕ (策略评估)
┌─────────────────────────────────────────────────────────┐
│ Redwood VLA (160M 参数, ~5Hz) — 直接控制策略               │
│                                                          │
│ 输入融合:                                                 │
│   ├── 预训练语言嵌入 (语言指令)                            │
│   ├── 预训练 ViT 特征 (图像)                              │
│   └── 本体感觉嵌入 (关节位置 + 力)                         │
│    ↓                                                    │
│ Transformer Blocks:                                      │
│   ├── 认知预测头: 估计手部和物体在图像空间的位置             │
│   └── 动作扩散头: 输出动作                                │
│    ↓                                                    │
│ 输出: EVE / NEO 动作                                     │
└─────────────────────────────────────────────────────────┘
```

**大空间目标查找流程**：
1. 训练多个 Redwood 策略检查点
2. 用 1XWM 预测每个检查点在相同初始状态下的成功率
3. 选择预测最好的检查点进行真实世界测试
4. 真实世界结果验证 1XWM 预测的准确性

**认知预测头的作用**：
- 不仅预测动作，还估计手部和物体的图像空间位置
- 帮助视觉表征接地，支持物体追踪

**优点**：
- 虚拟评估加速迭代：无需真实世界测试即可比较策略
- 从失败中学习：同时学习成功和失败 rollout
- 板载运行：160M 参数，无需云端

**缺点**：
- 推理延迟高：1XWM 生成 5 秒视频需要 11 秒
- 无显式空间记忆：依赖视觉匹配而非坐标
- Redwood 频率低 (~5Hz)，实时性不如 Figure

### 2.4 Tesla Optimus — FSD 占用网络迁移

**核心机制**：占用网络 (Occupancy Network) + 统一 AI 架构

```
┌─────────────────────────────────────────────────────────┐
│ 8 个 RGB 摄像头 (360° 覆盖)                               │
│  ├── 头部前视双目 (物体操作 + 路径规划)                    │
│  ├── 躯干 4 个广角 (导航 + 自碰撞避免)                     │
│  └── 下巴下视双目 (脚部放置 + 手部近身任务)                 │
└─────────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────────┐
│ Hydranet 多任务视觉骨干网络                               │
│                                                          │
│ 占用网络:                                                 │
│   ├── 体素化: 默认 33cm，近处 10cm                         │
│   ├── 预测: 占用状态 + 速度向量                            │
│   └── 语义: 区分移动车辆/静态建筑/路缘                      │
│                                                          │
│ 表面确定:                                                 │
│   ├── 高程、材质、可导航性                                 │
│   └── 车道线、路缘、减速带                                 │
└─────────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────────┐
│ VLA Transformer (50 Hz)                                  │
│ 输入: 视觉 token + 语言目标 + 时间上下文                   │
│ 输出: 16 步动作块 (30-40ms)                               │
│    ↓                                                    │
│ MPC → 关节扭矩 → 执行器 (1 kHz)                           │
└─────────────────────────────────────────────────────────┘
```

**大空间目标查找**：
- 占用网络维护 3D 体素地图，每个体素包含占用状态和语义
- 物体位置编码在体素地图中，支持跨房间查询
- 统一架构：无分层，单一网络处理所有任务

**优点**：
- 显式 3D 空间表示：体素地图天然支持空间查询
- 统一架构：无信息损失，梯度流畅传播
- 大规模数据：82 亿英里车辆数据迁移

**缺点**：
- 计算资源需求高：~500 TOPS AI5 芯片
- 纯视觉方案：遮挡和深度推断是软件问题
- 无显式物体实例记忆：体素地图不区分"同一物体的不同时刻"

- 工具调用：可调用 Google Search 等外部工具
- 代码执行：支持复杂空间计算

- 不直接控制机器人：需要连接外部 VLA

- 无显式空间记忆：依赖上下文窗口

### 2.6 NVIDIA Isaac — GR00T N1.7

**核心机制**：EgoScale 预训练 + Action Cascade 双系统

```
┌─────────────────────────────────────────────────────────┐
│ Cosmos-Reason2-2B VLM 骨干 (System 2)                    │
│  ├── SigLip2 视觉编码器                                  │
│  ├── T5 文本编码器                                      │
│  └── 本体感觉 MLP (按 embodiment ID 索引)                 │
└─────────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────────┐
│ 32 层 Diffusion Transformer (System 1)                   │
│  ├── Flow Matching 动作生成                              │
│  ├── AdaLN 扩散步条件                                    │
│  └── 输出: 连续动作向量                                   │
└─────────────────────────────────────────────────────────┘
```

**大空间目标查找**：
- EgoScale 预训练：20,854 小时第一人称人类视频
- 跨本体支持：Unitree G1, AGIBot Genie-1, Fourier GR-1
- 开源生态：HuggingFace + GitHub，社区可扩展

**优点**：
- 首个灵巧度 Scaling Law：人类数据从 1K 到 20K 小时，任务完成率翻倍
- 商业许可：支持生产部署
- 开源：模型权重和代码完全开放

**缺点**：
- 无显式空间记忆模块
- 依赖外部系统实现长期导航
- 需要微调才能适配新环境

### 2.7 Skild AI — Omni-Bodied Brain ⭐ 新增

**核心机制**：全具身智能 (Omni-Bodied) + 分层架构 + 上下文学习

```
┌─────────────────────────────────────────────────────────┐
│ Skild Brain — 全具身机器人基础模型                         │
│                                                          │
│ 训练数据:                                                 │
│   ├── 互联网人类视频 (大规模预训练)                         │
│   ├── 大规模仿真 (100,000+ 不同形态机器人)                  │
│   └──  targeted 真实世界数据 (后训练)                      │
│                                                          │
│ 架构: HPT (Heterogeneous Pre-trained Transformers)        │
│   ├── Stems (Tokenizers): 对齐多模态输入到共享 token 空间   │
│   ├── Shared Transformer Trunk: 任务无关表征               │
│   └── Task-Specific Heads: 轻量解码器                      │
└─────────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────────┐
│ 分层控制:                                                 │
│   ├── 高层: 低频操作和导航策略                             │
│   └── 低层: 高频关节级控制                                │
└─────────────────────────────────────────────────────────┘
```

**大空间目标查找**：
- **世界模型与记忆**：系统构建物体、可供性 (affordances) 和空间关系的内部模型，跨任务和时间持久化
- **上下文学习**：通过分析动作何时不生效，机器人发展出类似"直觉"的能力，动态调整行为
- **全具身训练**：100,000 种不同机器人在仿真中训练，迫使模型学习适应策略而非记忆特定方案

**关键特点**：

| 特点 | 说明 |
|------|------|
| **全具身智能** | 同一模型控制四足、人形、桌面机械臂、移动操作臂等 |
| **上下文学习** | 毫秒到分钟级的适应，应对形态变化和环境变化 |
| **仿真规模** | 数千个机器人实例，数千个环境，数千年仿真经验 |
| **数据增强** | NVIDIA Cosmos Transfer 生成环境变化 |

**优点**：
- 极强的泛化能力：零样本控制未见过的机器人形态
- 上下文学习：动态适应新环境，无需预编程
- 仿真规模：数千年仿真经验在数天内获得

**缺点**：
- 工业场景优先：目前主要面向工业自动化，非家庭环境
- 无显式空间记忆文档：世界模型细节未完全公开
- 依赖 NVIDIA 生态：Isaac Lab + Cosmos 训练基础设施

## 三、方案对比总结

### 3.1 记忆机制对比

| 公司 | 记忆类型 | 时长 | 可解释性 | 空间精度 |
|------|---------|------|---------|---------|
| **Figure AI** | 隐式潜向量 | 秒级 (S1) + 隐式 (S2) | 低 (黑盒) | 依赖外部 SLAM |
| **PI** | 视频短期 + 语言长期 | 6-54 秒 + 15 分钟 | 高 (自然语言) | 语言描述位置 |
| **1X** | 世界模型预测 | 未来 5 秒 | 中 (视频) | 视觉匹配 |
| **Tesla** | 占用网络体素地图 | 持续维护 | 中 (体素网格) | 高 (10cm 精度) |
| **Google** | 上下文窗口 | 128k tokens | 高 (文本) | 2D 指向 + 3D 检测 |
| **NVIDIA** | 隐式表征 | 推理时 | 低 | 依赖外部系统 |
| **Skild** | 世界模型 + 上下文学习 | 跨任务持久化 | 中 | 内部空间模型 |
