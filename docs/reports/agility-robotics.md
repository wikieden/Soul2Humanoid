## 二、硬件架构

### Digit 机器人规格

| 参数 | Digit 2.0 |
|------|-----------|
| **身高** | ~175 cm |
| **体重** | ~65 kg |
| **自由度 (DoF)** | 16（每条腿 5，每只手臂 3，躯干 0） |
| **行走速度** | ~1.5 m/s |
| **续航** | ~2-4 小时（可热插拔电池） |
| **负载能力** | ~16 kg（单 tote 搬运） |
| **传感器** | 头部 Intel RealSense（深度相机）、躯干 IMU、关节编码器 |
| **计算单元** | 板载 Intel CPU + NVIDIA GPU（用于感知） |
| **末端执行器** | 定制化夹爪（针对 tote/箱子优化） |

### 设计哲学

- **场景优先**：Digit 的设计完全围绕"在仓库中搬运塑料 tote"这一个任务优化，而非追求通用性
- **成本可控**：相比 Figure 02 或 Tesla Optimus，Digit 的硬件复杂度更低（无五指灵巧手、无躯干自由度），便于量产和降本
- **热插拔电池**：支持连续作业，电池更换可在 1-2 分钟内完成
- **安全第一**：具备摔倒检测和自我保护机制，减少对周围人员和设备的伤害风险

## 三、AI 与软件架构

### 核心特点：分层控制 + 有限的学习成分

Agility Robotics 的 AI 架构是**偏传统的分层控制方案**，与 Physical Intelligence 的端到端 VLA 或 Tesla 的神经网络方案形成鲜明对比。

```
┌─────────────────────────────────────┐
│  任务调度层 (Task Scheduler)         │  ← 仓库 WMS 集成，接收搬运指令
├─────────────────────────────────────┤
│  高层规划 (High-Level Planner)       │  ← 路径规划、避障、抓取策略选择
├─────────────────────────────────────┤
│  运动控制 (Locomotion Control)       │  ← 双足动态行走（基于 ZMP + 简化模型）
├─────────────────────────────────────┤
│  底层关节控制 (Joint Control)        │  ← PD 控制 + 力矩前馈
└─────────────────────────────────────┘
```

![agility-robotics 架构图](../assets/agility-digit-architecture.svg)

### 行走控制：基于模型的方法

- **线性倒立摆模型 (LIPM)** + **零力矩点 (ZMP)** 控制
- 步态生成采用**预定义步态库**，而非神经网络生成
- 通过**模型预测控制 (MPC)** 在线调整步态以应对扰动
- 这种方案**可靠性强、可解释性好**，但在非结构化地形上的泛化能力有限

### 操作（Manipulation）

- Digit 的手臂操作相对简单：主要是**抓取和放置 tote**
- 使用**基于视觉的伺服控制 (Visual Servoing)** 定位 tote
- 夹爪开合由简单的**力/位置混合控制**实现
- 2024 年公布的 Manipulation System 引入了更多自动化，但仍以传统控制为主

### 感知的角色

- 头部 RealSense 深度相机用于**障碍物检测**和** tote 定位**
- 使用经典的**点云处理 + 3D 包围盒检测**识别 tote
- 尚未公开使用大规模神经网络进行场景理解或语义分割的证据

## 四、数据策略

### 数据来源

| 来源 | 描述 |
|------|------|
| **仿真训练** | 使用简化物理模型进行步态预训练和验证 |
| **真实部署数据** | 从 Amazon、GXO 等客户现场收集运行数据 |
| **遥操作调试** | 工程师远程介入处理 corner case |

### 数据飞轮

Agility 的**数据飞轮相对较弱**，原因：
- 控制方案以模型为主，不需要海量端到端训练数据
- 步态和操作策略变更频率低，更多是参数微调
- 客户现场的部署数据主要用于**故障诊断**和**性能监控**，而非训练新模型

不过，随着 Digit 部署数量增加（2024 年宣布目标"数百台"），真实世界运行数据积累仍具有长期价值。

## 五、商业化与竞争格局

### 商业模式

- **RaaS (Robot as a Service)**：客户按小时或按任务付费，而非购买硬件
- **合作伙伴**：Amazon（试点）、GXO（多年协议）、未来可能扩展至其他 3PL 和零售商
- **单位经济学**：强调 Digit 的运营成本低于人类工人（目标 $10-15/小时全包成本）

### 竞争优势

| 优势 | 说明 |
|------|------|
| **场景聚焦** | 不做通用，只做 tote 搬运，降低技术风险和成本 |
| **先发部署** | 最早在真实仓库（Amazon）进行规模化测试 |
| **硬件成熟** | Cassie/Digit 历经近 10 年迭代，双足行走可靠性高 |
| **传统控制可靠** | 基于模型的控制在已知场景中可预测性强 |

### 竞争劣势

| 劣势 | 说明 |
|------|------|
| **技术天花板低** | 传统控制方案难以扩展到更复杂、非结构化的任务 |
| **通用性差** | 换一个任务（如拧螺丝、开门）需要大量重新开发 |
| **学习成分少** | 难以从数据中获得能力提升，与新一波 VLA 公司差距拉大 |
| **资本效率存疑** | 低技术壁垒可能导致被更通用的机器人替代 |

### 与竞品对比

| 维度 | Agility Digit | Figure 02 | Tesla Optimus |
|------|--------------|-----------|---------------|
| **场景** | 仓储 tote 搬运 | 通用工业/家用 | 通用工业/家用 |
| **AI 架构** | 传统分层控制 | Helix VLA（端到端） | FSD 神经网络 |
| **灵巧手** | 简单夹爪 | 11-DoF 五指手 | 11-DoF 五指手 |
| **部署状态** | 小规模试点 | 宝马/BMW 试点 | 工厂内部测试 |
| **成本定位** | 中等（RaaS） | 高 | 目标低成本 |

## 七、总结与展望

### 技术路线判断

Agility Robotics 代表了人形机器人领域的**"务实派"**——用成熟可靠的控制方案解决一个具体的商业问题。这条路线的**短期可行性强**，但**长期天花板明显**。

- **短期（2024-2026）**：有望率先实现人形机器人的商业闭环（在仓库中真正创造经济价值）
- **中期（2026-2028）**：如果 VLA 公司（Figure、Tesla、PI）的技术快速成熟并降本，Digit 的专用优势可能被通用机器人侵蚀
- **长期**：要么转型拥抱 AI/学习，要么退守特定 niche 市场

### 核心关注点

1. **Amazon/GXO 试点的实际运营数据**：每小时搬运量、故障率、维护成本
2. **单位经济学进展**：RaaS 定价是否能真正实现盈利
3. **技术路线是否转向学习**：是否会引入神经网络替代部分传统控制
